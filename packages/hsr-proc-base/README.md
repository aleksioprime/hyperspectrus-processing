# hsr-proc-base

> **Зеркало.** Каталог собран скриптом `tools/sync_contract.py` из монорепозитория
> комплекса. Правки вносятся там; всё, что изменено здесь, будет затёрто при
> следующем обновлении, а до того уронит проверку `tests/test_mirror.py`.

Контракт обработки мультиспектральных серий: описание входных и выходных данных и реестр реализаций.

**Алгоритма здесь нет вовсе.** Любая реализация поставляется отдельным пакетом и подключается точкой входа - рабочее место выбирает её по имени, а не импортирует конкретный модуль. Благодаря этому алгоритм заменяется установкой другого пакета, без правки приложения.

Как оформить, подключить и заменить такой пакет - [README.md](../../README.md#контракт-обработки).

## Состав

| Модуль | Назначение |
|---|---|
| `models.py` | Спектральный куб, матрица коэффициентов перекрытий, параметры и результат |
| `contract.py` | Протокол `Processor` - единственное, что связывает алгоритм с рабочим местом |
| `registry.py` | Поиск реализаций среди точек входа, выбор по имени |
| `loading.py` | Сборка куба из файлов серии, снятой устройством |

Пакет не зависит ни от интерфейса, ни от базы данных: на вход поступают массивы и коэффициенты, на выход - карты и показатели. Выполняется только на рабочем месте врача - снимки пациентов не покидают компьютер.

Зависимости намеренно ограничены `numpy` и `pillow`; тяжёлые библиотеки объявляет у себя пакет с алгоритмом.

## Проверка подключения

```bash
uv run python -m hsr_proc
```

Команда выводит все найденные реализации и отмечает выбранную.

## Эталонная реализация

Повторяет обработку из прототипа рабочего места и позволяет пользоваться программой до подключения рабочего алгоритма: оптическая плотность, решение системы по матрице коэффициентов, карта THb, выделение очага порогом Отсу и расчёт коэффициента s. В отличие от прототипа система решается сразу для всех пикселей - поэлементный цикл по кадру 1280×720 занимал минуты.
