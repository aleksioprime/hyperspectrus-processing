# hsr-proc-algo

Пакет алгоритма обработки: восстановление концентраций хромофоров по спектральному кубу. Это то место, где живёт расчёт.

## Как считает

Прибор снимает один участок кожи в нескольких спектрах. Разные хромофоры по-разному поглощают свет разных длин волн, поэтому по яркостям одного пикселя на всех кадрах серии можно восстановить, сколько в нём каждого вещества.

1. **Яркости переводятся в оптическую плотность** - `-log10` от яркости. Плотность связана с концентрацией поглотителя линейно, и это превращает задачу в систему линейных уравнений. Яркость снизу ограничена: логарифм нуля обратился бы в бесконечность и испортил бы весь столбец.
2. **Решается система уравнений** - по матрице коэффициентов перекрытия из справочника. Спектров больше, чем хромофоров, поэтому решение ищется методом наименьших квадратов, сразу для всех пикселей одним вызовом: поэлементный цикл по кадру 1280×720 занимал минуты.
3. **Складывается карта THb** - общая концентрация гемоглобина, сумма модулей `HbO2` и `Hb`. Справочник ведёт пользователь рабочего места, и нужных обозначений в нём может не оказаться: тогда THb считается из того, что есть, а `notes` объясняет врачу, из чего именно.
4. **Выделяется область поражения** - карта THb сглаживается гауссовым ядром и делится порогом Отсу на очаг и здоровую кожу. Сглаживание нужно, чтобы пиксельный шум не дробил очаг на отдельные пятна.
5. **Считаются показатели** - средние THb внутри очага и снаружи и их отношение, коэффициент s. Именно он показывает врачу динамику между сеансами.

Это действующий расчёт рабочего места и отправная точка исследования: он проходит приёмку целиком, поэтому любое изменение сразу видно на фоне рабочего поведения. Переписывать всё сразу не нужно - можно заменить сегментацию, оставив восстановление концентраций, и наоборот.

## Что менять

`processor.py` и `segmentation.py` - предмет исследования, правьте их свободно. Согласовано с приложением и не меняется только это:

| Что | Где | Почему |
|---|---|---|
| Имя пакета, модуля, точка входа | `pyproject.toml` | по ним рабочее место находит реализацию |
| `name = "algo"` | `processor.py` | по нему рабочее место выбирает расчёт |

Поле `version` поднимается при любом изменении расчёта: оно попадает в карточку сеанса, и по нему сравнивают результаты. Назад версия не идёт.

## Как проверять

```bash
uv run hsr-proc-check hsr-proc-algo          # приёмка целиком
uv run pytest packages/hsr-proc-algo         # приёмка и собственные проверки пакета
uv run hsr-proc-run --synthetic --out out    # посмотреть на карты глазами
```

Допуски приёмки лежат в `src/hsr_proc_algo/conformance.toml` и едут вместе с пакетом. Для расчёта на другой математической модели там же объявляются послабления и причина каждого.

## Состав

| Файл | Назначение |
|---|---|
| `processor.py` | Расчёт концентраций и показателей |
| `segmentation.py` | Сглаживание и выделение области поражения |
| `conformance.toml` | Допуски приёмки и объявленные отступления |
| `tests/conftest.py` | Построение серии с заранее известным ответом |
| `tests/test_processor.py` | Проверка обратимостью: по известным концентрациям алгоритм обязан вернуть их же |
| `tests/test_segmentation.py` | Порог Отсу и сглаживание |
| `tests/test_conformance.py` | Приёмочный набор целиком |

Зависимости алгоритма объявляются здесь же: в контракт и в другие пакеты они не попадут.
