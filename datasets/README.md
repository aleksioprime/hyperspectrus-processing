# Тестовые данные

## Синтетические серии

Отдельных файлов не требуют: серии строятся кодом в `hsr_proc_conformance.data`. Задача обратима, и это даёт проверку без единого реального снимка - по заданным концентрациям считаются яркости, и алгоритм обязан вернуть исходные концентрации.

```bash
uv run hsr-proc-run --synthetic --out out
```

## Настоящие кадры

Кладутся в `datasets/real/<название>/` в той же раскладке, в какой их пишет прибор:

```
datasets/real/пример/
└── jpeg/
    └── 1/
        ├── 450nm.jpg
        ├── 517nm.jpg
        ├── 671nm.jpg
        └── 939nm.jpg
```

Имя файла содержит длину волны в нанометрах - по нему кадр и попадает в нужный слой куба. Читаются `jpg`, `png`, `tif`, `bmp`; файлы `dng` контракт не разбирает, для них алгоритму нужны собственные зависимости.

```bash
uv run hsr-proc-run datasets/real/пример --reference datasets/reference.json --out out
```

**Каталог `real/` в репозиторий не идёт** - он закрыт в `.gitignore`. Снимки пациентов не попадают в репозиторий ни при каких условиях, даже обезличенные: обезличенность снимка кожи решается не тем, что с него стёрли имя файла. Набор для работы передаётся отдельно и по договорённости.

## Справочник

`reference.json` - пример файла коэффициентов перекрытия для `hsr-proc-run`. Строки соответствуют длинам волн, столбцы - хромофорам, значения показывают, насколько хромофор поглощает на этой длине волны.

Значения в примере синтетические: они годятся, чтобы посмотреть на работу алгоритма, и не годятся, чтобы делать выводы о веществах. Рабочий справочник ведёт издатель, и он приходит на рабочее место вместе с моделью прибора.
