# hsr-proc-conformance

Приёмочные проверки пакетов с алгоритмами обработки. Один и тот же набор запускают обе стороны: разработчик алгоритма перед отправкой и издатель на приёмке. Разойтись в выводах они не могут - проверки и данные одни и те же.

## Подключение к своему пакету

```python
from hsr_proc_conformance import ProcessorConformance
from hsr_proc_algo import AlgoProcessor


class TestМойАлгоритм(ProcessorConformance):
    processor = AlgoProcessor()
    distribution = "hsr-proc-algo"
```

Весь набор достаётся наследованием и обновляется вместе с пакетом. Свои проверки добавляются обычными методами класса.

## Команды

```bash
hsr-proc-check                      # проверить установленный пакет целиком
hsr-proc-check --level contract     # только обязательный уровень
hsr-proc-check --report приёмка.md  # отчёт для передачи и хранения
hsr-proc-run --synthetic --out out  # прогон на синтетической серии
hsr-proc-run ./серия --reference справочник.json
```

`hsr-proc-check` проверяет **установленный** пакет, а не исходники: точки входа читаются из метаданных окружения, и разница между «написано в pyproject.toml» и «установлено» - самая частая причина пропавшего алгоритма.

## Состав

| Модуль | Назначение |
|---|---|
| `suite.py` | Сами проверки: класс `ProcessorConformance` |
| `data.py` | Синтетические наборы с заранее известным ответом |
| `packaging.py` | Оформление пакета: точка входа, зависимости, метаданные |
| `sandbox.py` | Наблюдение за записью файлов, сетью и сменой каталога |
| `config.py` | Допуски приёмки и объявленные отступления |
| `report.py` | Отчёт приёмки |
| `runner.py` | Прогон алгоритма на кадрах без рабочего места |

## Уровни

| Метка | Что проверяет | Что значит неудача |
|---|---|---|
| `contract` | Соответствие контракту | Пакет не принимается |
| `numeric` | Числа на синтетических наборах | Разбирательство; для другой модели - объявленное отступление |
| `budget` | Время обработки кадра прибора | Замечание и число в отчёте |
