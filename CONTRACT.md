# Контракт обработки

Документ описывает всё, что рабочее место врача ожидает от пакета с алгоритмом. Он самодостаточен: читать исходники комплекса не нужно, достаточно контракта в [`packages/hsr-proc-base`](packages/hsr-proc-base) и этого текста.

## Задача

Прибор снимает один участок кожи в восьми спектрах. Получается серия кадров: тот же участок, та же геометрия, разная длина волны. Известно, насколько каждый хромофор поглощает свет на каждой из этих длин волн - это матрица коэффициентов перекрытия из справочника рабочего места.

Алгоритм восстанавливает по серии карты концентраций хромофоров, считает по ним карту общей концентрации гемоглобина (THb), выделяет на ней область поражения и возвращает средние концентрации в поражении и в здоровой коже вместе с их отношением. Отношение и есть то число, ради которого врач проводит сеанс.

Дальше рабочее место сохраняет карты на диск, пишет показатели в базу и показывает результат. Алгоритм в этом не участвует.

## Реализация

Реализация - объект с тремя членами:

```python
class MyProcessor:
    name = "myalgo"  # имя, по которому реализацию выбирают в настройках
    version = "2.1"  # попадает в результат и в карточку сеанса

    def process(self, request, progress=None):
        ...
        return ProcessingResult(...)
```

Формально это протокол `hsr_proc.Processor`. Наследоваться ни от чего не нужно: проверяется наличие членов, а не происхождение класса.

### Вход

`ProcessingRequest` состоит из трёх частей:

| Поле | Содержание |
|---|---|
| `cube` | `SpectralCube`: массив `(спектры, высота, ширина)` типа `float32` со значениями от 0 до 1 и кортеж длин волн в том же порядке |
| `overlap` | `OverlapMatrix`: коэффициенты перекрытия, строки - длины волн, столбцы - хромофоры |
| `params` | `ProcessingParams`: общий параметр `gaussian_sigma` и словарь `extra` для собственных настроек алгоритма |

Порядок строк матрицы **не обязан** совпадать с порядком слоёв куба: порядок кадров задаёт прибор, порядок строк - справочник рабочего места. Привести их в соответствие нужно вызовом `request.overlap.aligned_to(request.cube)` - он же проверит, что коэффициенты есть для всех снятых длин волн. Без этого вызова концентрации окажутся перепутаны молча, а результат при этом будет выглядеть правдоподобно.

### Выход

`ProcessingResult` со всеми заполненными полями:

| Поле | Содержание |
|---|---|
| `concentrations` | Карты концентраций по обозначению хромофора: `{"HbO2": массив, "Hb": массив}`. Карта нужна по каждому хромофору справочника |
| `thb_map` | Карта общей концентрации гемоглобина |
| `lesion_mask` | Двоичная маска области поражения того же размера, что и кадр |
| `metrics` | `ProcessingMetrics`: коэффициент s и средние THb в поражении и в коже |
| `segmentation` | `SegmentationInfo`: способ выделения, порог и использованное сглаживание |
| `processor` | Имя и версия: ровно `f"{self.name} {self.version}"` |
| `notes` | Пояснение для врача: допущения, замены, предупреждения |

Карты - `float32` размером с кадр, маска - `bool`, ни одного NaN и ни одной бесконечности. Пропуск в карте дошёл бы до карточки сеанса молча, и отличить его от настоящего результата врач не смог бы.

## Правила

**Никакого ввода-вывода.** Пакет не читает базу, не пишет файлы и не знает про интерфейс. У врача каталог установки бывает закрыт на запись, а сеть закрыта совсем: это медицинские данные, и они не покидают компьютер. Файлы сохраняет рабочее место.

**Вход не меняется.** Запрос принадлежит рабочему месту, и тем же кубом оно обрабатывает соседние участки сеанса. Правка на месте испортила бы соседний участок, причём только при обработке нескольких участков подряд.

**Один и тот же вход даёт один и тот же выход.** Случайная инициализация без фиксированного зерна означает, что повторная обработка сеанса даст врачу другие числа при тех же снимках.

**Сообщать о ходе работы.** Обработка занимает секунды и идёт в фоновом потоке; вызывайте `progress(процент, "что делается")`, если он передан. Удобно через `hsr_proc.report(progress, 30, "Расчёт концентраций")`. Проценты не убывают, последний равен ста.

**Ошибки - исключениями контракта.** Непригодные данные - `InvalidInput`, неудача расчёта - `ProcessingFailed`. Остальные исключения рабочее место показывает врачу как непредвиденный сбой: причина остаётся в журнале, а врач остаётся без объяснения.

**Неполный справочник - не повод молчать.** Справочник ведёт пользователь, и в нём может не оказаться `Hb` или `HbO2`. Допустимо отказаться считать, допустимо посчитать и объяснить в `notes`, из чего получен THb. Недопустимо посчитать молча.

**Тяжёлые зависимости объявляйте у себя.** `opencv`, `scikit-image`, `torch` ставит пакет с алгоритмом, а не контракт.

## Оформление пакета

```
hsr-proc-myalgo/
├── pyproject.toml
├── README.md
├── src/
│   └── hsr_proc_myalgo/
│       ├── __init__.py
│       ├── py.typed
│       └── processor.py
└── tests/
    └── test_conformance.py
```

Главное в `pyproject.toml` - раздел точек входа: он и делает алгоритм видимым для рабочего места. Без него алгоритма для программы не существует, и никакого сообщения об ошибке при этом не появится - реализации просто не будет в списке.

```toml
[project]
name = "hsr-proc-myalgo"
version = "2.1.0"
requires-python = ">=3.11"
dependencies = [
    "hsr-proc-base>=0.1,<0.2",
    "numpy>=2.1",
    "opencv-python-headless>=4.10",   # зависимости самого алгоритма
]

[project.entry-points."hsr_proc.processors"]
myalgo = "hsr_proc_myalgo:MyProcessor"
```

Метка слева произвольна и ни на что не влияет: реализация называет себя сама полем `name`. Справа - модуль и класс (или функция), дающие объект реализации.

Готовая заготовка со всем этим - в [`template/hsr-proc-myalgo`](template/hsr-proc-myalgo). Проще скопировать её, чем собирать пакет заново.

## Проверки

Пакет проверяется одной командой, и она же запускается на приёмке:

```bash
uv run hsr-proc-check
```

Уровень `contract` обязателен. Уровень `numeric` сверяет числа с синтетическими наборами: по заданным концентрациям строятся яркости, и алгоритм обязан вернуть исходные концентрации. Уровень `budget` меряет время на кадре прибора.

Проверки подключаются к вашим тестам наследованием:

```python
from hsr_proc_conformance import ProcessorConformance
from hsr_proc_myalgo import MyProcessor


class TestМойАлгоритм(ProcessorConformance):
    processor = MyProcessor()
    distribution = "hsr-proc-myalgo"
```

Своих проверок это не отменяет: набор проверяет соответствие контракту, а не то, что алгоритм решает задачу лучше прежнего.

## Другая модель

Синтетические наборы построены на линейной модели: оптическая плотность складывается из концентраций по матрице коэффициентов. Алгоритм, учитывающий рассеяние или обученный на снимках, эту модель точно не воспроизводит и провалит сверку концентраций, будучи при этом лучше эталонного.

Для таких алгоритмов допуски ослабляются, но только вслух: послабление объявляется в `pyproject.toml` вместе с причиной и попадает отдельным разделом в отчёт приёмки.

```toml
[tool.hsr_proc_conformance]
profile = "custom"
concentration_atol = 1e-3
deviations = [
    "Модель учитывает рассеяние, точное обращение линейной системы не воспроизводится",
]
```

Тихо ослабить допуск не получится: проверка `test_послабления_объяснены` требует объяснения к каждому послаблению. Что остаётся обязательным при любом профиле: весь уровень `contract`, выделение очага и коэффициент s. Отношение средних безразмерно и от модели не зависит - в наборе очаг втрое насыщеннее кожи, и это обязан увидеть любой алгоритм.

## Передача и версии

`name` между версиями **не меняется**: по нему отличают, каким алгоритмом посчитан сеанс, и смена имени разорвала бы связь с уже обработанными сеансами.

`version` поднимается при любом изменении расчёта - она попадает в карточку сеанса, и по ней сравнивают результаты. Уже обработанные сеансы не пересчитываются: чтобы получить результат новым алгоритмом, обработку запускают заново.

К передаче прикладываются колесо `.whl`, отчёт `hsr-proc-check --report` и описание изменений. Дальше пакет ставится в окружение сборки рабочего места, проходит те же проверки у издателя и выходит к клиникам с очередной полной версией программы: рабочее место поставляется одним исполняемым файлом, и доустановить в него пакет некуда.
