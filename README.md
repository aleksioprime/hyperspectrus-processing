# hyperspectrus-processing

Репозиторий для разработки алгоритма обработки HyperSpectRus

## Начало работы

```bash
git clone https://github.com/aleksioprime/hyperspectrus-processing
cd hyperspectrus-processing
uv sync --all-packages
```

Расчёт пишется в
[`packages/hsr-proc-algo/src/hsr_proc_algo/processor.py`](packages/hsr-proc-algo/src/hsr_proc_algo/processor.py).
Ищите пометки `ЗДЕСЬ`. Имя пакета, модуль, точка входа и имя реализации `algo`
уже согласованы с рабочим местом — менять их не нужно.

```bash
uv run python -m hsr_proc                         # пакет виден приложению
uv run hsr-proc-check hsr-proc-algo --level contract
uv run hsr-proc-check hsr-proc-algo              # полная приёмка
uv run hsr-proc-run --synthetic --out out         # карты и metrics.json
```

Исходная реализация возвращает пустые карты правильного вида. Уровень
`contract` на ней проходит, числовые проверки ожидаемо падают до реализации
расчёта.

## Структура

| Каталог | Назначение |

## Контракт обработки

Контракт описывает всё, что рабочее место врача ожидает от пакета с алгоритмом.
Читать исходники приложения для реализации расчёта не требуется.

### Задача

Прибор снимает один участок кожи в нескольких спектрах: геометрия кадра одна,
длины волн разные. Рабочее место передаёт спектральный куб и матрицу
коэффициентов поглощения хромофоров.

Алгоритм должен восстановить карты концентраций, вычислить карту общей
концентрации гемоглобина (THb), выделить область поражения и вернуть средние THb
в поражении и коже вместе с их отношением. Сохранением файлов, базой данных и
интерфейсом занимается рабочее место.

### Реализация

Реализация — объект с тремя членами:

```python
class AlgoProcessor:
    name = "algo"
    version = "0.1"

    def process(self, request, progress=None):
        ...
        return ProcessingResult(...)
```

Это протокол `hsr_proc.Processor`; наследоваться от специального класса не
нужно. `name` должно оставаться равным `algo`, а `version` поднимается при любом
изменении расчёта.

#### Вход

`ProcessingRequest` содержит:

| Поле | Содержание |
|---|---|
| `cube` | `SpectralCube`: массив `(спектры, высота, ширина)` типа `float32`, значения от 0 до 1 и длины волн в порядке кадров |
| `overlap` | `OverlapMatrix`: строки соответствуют длинам волн, столбцы — хромофорам |
| `params` | `ProcessingParams`: общий `gaussian_sigma` и словарь `extra` для параметров алгоритма |

Порядок строк матрицы может отличаться от порядка слоёв куба. Перед расчётом
обязательно вызывайте:

```python
matrix = request.overlap.aligned_to(request.cube)
```

Метод одновременно переставляет строки и проверяет наличие коэффициентов для
всех снятых длин волн.

#### Выход

Нужно вернуть `ProcessingResult` со всеми полями:

| Поле | Содержание |
|---|---|
| `concentrations` | Карта `float32` размером с кадр для каждого хромофора справочника |
| `thb_map` | Карта общей концентрации гемоглобина `float32` |
| `lesion_mask` | Маска поражения типа `bool` |
| `metrics` | Коэффициент s и средние THb в поражении и коже |
| `segmentation` | Метод сегментации, порог и использованное сглаживание |
| `processor` | Ровно `f"{self.name} {self.version}"` |
| `notes` | Допущения и предупреждения для врача |

Размер всех карт совпадает с размером кадра. NaN и бесконечные значения не
допускаются.

### Обязательные правила

- Не читать и не записывать файлы, не обращаться к базе, интерфейсу или сети.
- Не изменять входной `ProcessingRequest` и содержащиеся в нём массивы.
- Один и тот же вход должен всегда давать один и тот же результат.
- Сообщать прогресс в неубывающих процентах, последний вызов — 100.
- Ошибки входных данных оформлять как `InvalidInput`, ошибки расчёта — как
  `ProcessingFailed`.
- При отсутствии `Hb` или `HbO2` либо отказать с понятной ошибкой, либо явно
  описать использованную замену в `notes`.
- Зависимости алгоритма, включая `opencv`, `scikit-image` или `torch`, объявлять
  только в `packages/hsr-proc-algo/pyproject.toml`.

### Подключение пакета

Рабочее место находит алгоритм по точке входа, а не прямым импортом:

```toml
[project]
name = "hsr-proc-algo"
requires-python = ">=3.11"
dependencies = [
    "hsr-proc-base>=0.1,<0.2",
    "numpy>=2.1",
]

[project.entry-points."hsr_proc.processors"]
algo = "hsr_proc_algo:AlgoProcessor"
```

Без этой записи реализация не появится в рабочем месте. Точка входа уже
настроена в пакете и обычно не требует изменений.

### Приёмочные проверки

Пакет [`hsr-proc-conformance`](conformance) используется только при разработке
и приёмке. Он предоставляет две команды:

- `hsr-proc-check` проверяет установленный пакет и формирует вердикт;
- `hsr-proc-run` запускает алгоритм на синтетической или файловой серии без
  рабочего места.

Уровни проверки:

| Уровень | Что проверяет |
|---|---|
| `contract` | Форму результата, типы, отсутствие NaN, неизменность входа, отсутствие файлового и сетевого ввода-вывода |
| `numeric` | Концентрации, THb, сегментацию и показатели на синтетических данных с известным ответом |
| `budget` | Время обработки кадра прибора |

```bash
uv run pytest
uv run pytest -m contract packages/hsr-proc-algo/tests
uv run hsr-proc-check hsr-proc-algo
uv run hsr-proc-check hsr-proc-algo --report приёмка.md
```

#### Другая математическая модель

Синтетическая проверка концентраций основана на линейной модели. Для алгоритма,
учитывающего рассеяние или использующего обученную модель, допустимо объявить
отступление в корневом `pyproject.toml`:

```toml
[tool.hsr_proc_conformance]
profile = "custom"
concentration_atol = 1e-3
deviations = [
    "Модель учитывает рассеяние, точное обращение линейной системы не воспроизводится",
]
```

Каждое ослабление допуска должно быть объяснено. Уровень `contract`, выделение
очага и коэффициент s остаются обязательными при любом профиле.

### Сборка и передача

Перед передачей алгоритма:

1. Добейтесь успешного `uv run hsr-proc-check hsr-proc-algo`.
2. Поднимите `AlgoProcessor.version` при любом изменении расчёта.
3. Соберите пакет: `uv build --package hsr-proc-algo`.
4. Передайте wheel из `dist/`, отчёт приёмки и описание изменений.

Пакет устанавливается в окружение сборки рабочего места и попадает в следующую
полную версию программы. Отдельно доустановить алгоритм в поставленное врачу
приложение нельзя.

## Тестовые данные

Синтетические серии создаются автоматически. Настоящие кадры кладутся в
`datasets/real/` по правилам из [`datasets/README.md`](datasets/README.md) и не
фиксируются в Git. Снимки пациентов не должны попадать в этот репозиторий.
